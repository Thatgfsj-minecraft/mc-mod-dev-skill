# 版本知识索引（environments/versions/）

按 **Minecraft 版本号**分文件夹组织版本知识。AI 查某个版本：直接进 `versions/<版本号>/README.md`。文件夹名必须是 **Minecraft Java Edition 的正式发布版本号**，精确匹配（禁止前缀 / glob 匹配，`1.21*` 会同时命中 1.21、1.21.1、1.21.11）；列目录展示时按版本号数值排序，不要按字典序。日期式新版本线（如 26.x）同样适用本目录方案。

## 使用规则

1. **Phase 0 识别出目标版本后**，先读对应版本的 `README.md` 版本卡，再读该文件夹下其他文件（如 `vs-*.md` 差异对照）。
2. 版本卡里的内容按**条目级可信标签**区分，不能混用：
   - 无标签 = **公开常识**（公开稳定知识，可用于环境卡交叉校验）；
   - `[公开文档：<来源>]` = 官方文档记载（如 NeoForge 升级 primer）；
   - `[实测：<方式>]` = 本组织在真实项目上编译 + 行为测试验证过；
   - `[未核实]` = 不确定，动手前必须走 `../../api-verification.md` 核实。
3. **目标版本没有文件夹** → 读**同发布线最近邻已覆盖版本**的版本卡做交叉校验（对照下方缺号说明；仍按该卡条目的可信级别使用）；完全没有邻卡 → 全程走核实流程，验证完成后按"新增版本"沉淀。
4. 允许缺号（短生命周期 / 热修版本可以不建）；缺了哪些号见下方缺号说明。

## 目录约定

```
versions/
  <mc版本>/README.md          版本卡：Java / 发布线 / Loader / 映射 / 构建系统（/ Gradle / 已验证依赖坐标）
  <mc版本>/vs-<其他版本>-<映射>.md   版本对差异（放在较旧版本文件夹下，从旧迁新的视角写，带适用边界标注）
```

## 新增版本

1. 复制下方模板建 `README.md`；**只填有把握的结构事实**，不确定的字段写 `[未核实]`；API 级 / 实测级条目必须带可信标签。
2. 差异经验必须先经真实项目验证（编译过 + 行为测试过）才能写入，并注明验证方式；每条标适用边界。
3. 更新本 README 的覆盖表与缺号说明（**这是版本覆盖的唯一事实来源**）。
4. 不需要修改 `SKILL.md`——新增版本 / Loader 不应触碰核心行为。
