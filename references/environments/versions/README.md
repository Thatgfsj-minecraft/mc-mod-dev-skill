# 版本知识索引（environments/versions/）

按 **Minecraft 版本号**分文件夹组织版本知识。AI 查某个版本：直接进 `versions/<版本号>/README.md`。

## 使用规则

1. **Phase 0 识别出目标版本后**，先读对应版本的 `README.md` 版本卡，再读该文件夹下其他文件（如 `vs-*.md` 差异对照）。
2. 版本卡里的内容分两种可信级别，**不能混用**：
   - **结构事实**：Java 要求、Loader / 映射可用性、时代特征——公开稳定知识，可用于环境卡交叉校验；
   - **已验证经验**：本组织在真实项目上编译 + 行为测试验证过的差异。没有标注的一律视为**未验证**，动手前必须走 `../../api-verification.md`。
3. 目标版本没有文件夹 → 该版本无任何知识记录，全程走核实流程；验证完成后按下面"新增版本"沉淀。
4. 文件夹名必须是**真实存在的 Java 版版本号**；允许缺号（短生命周期的版本可以不建）。

## 目录约定

```
versions/
  <mc版本>/README.md          版本卡：Java / Loader / 映射 / 时代特征 / 已验证经验索引
  <mc版本>/vs-<其他版本>-<映射>.md   版本对差异（放在较旧版本文件夹下，从旧迁新的视角写）
```

## 新增版本

1. 复制下方模板建 `README.md`；**只填有把握的结构事实**，不确定的字段写"未核实"。
2. 差异经验必须先经真实项目验证（编译过 + 行为测试过）才能写入，并注明验证方式。
3. 更新本 README 的覆盖表和根 `README.md`。

### 版本卡模板

```markdown
# Minecraft <版本号>

> 可信级别声明：本卡除「已验证经验」外均为**结构事实 / 公开常识**；API 差异动手前必须按 api-verification.md 核实。

## 基本盘

| Java | … |

- …

## 已验证经验
- 暂无 / 列出文件
```
